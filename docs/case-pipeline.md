# Как собирать кейс на kovtun.studio

Срез рабочего процесса по итогам кейсов «Капиталъ Информ» и «Трубоварня Еремеева»
(июль 2026), дополнен по итогам страниц услуг и аудита сайта (сентябрь 2026).
Файл нужен, чтобы новый чат начинал не с разведки, а с дела.

Разделы «Тексты», «Верстка блоков», «Мета и картинки» и «Новая страница или блок»
относятся не только к кейсам: те же правила действуют для статей блога и для блоков
на страницах услуг. Скилл `seo-stati-dlya-bloga` описывает процесс статьи, а здешние
правила — как ее сверстать и оформить, чтобы не переделывать дважды.

**Этот файл — единственное место, где правила записаны полностью.** Скилл статей
и память проекта только ссылаются сюда. Если правило нужно поправить — правьте здесь,
и копии не разойдутся.

У скилла `seo-stati-dlya-bloga` две копии. Рабочая — облачная, в скиллах claude.ai:
она грузится с любого компьютера и из браузера. Дисковая в `Cowork\skills` резервная,
правится из чата и оттуда заливается в облако. Признак, что подхватилась
необновленная копия: в ней нет шага 4.5 со ссылкой сюда — тогда открывайте этот
файл вручную.

## Что такое кейс в этом проекте

Кейс = папка с двумя файлами:

- `case.md` — шапка и тексты. Разбирается `src/lib/case-content.ts`, схема в `src/content.config.ts`
- `gallery.yaml` — раскладка изображений

Папки кейсов разложены по двум группам:

```
cases/
  published/     — кейс собран и стоит на сайте
  unpublished/   — материал есть, кейса еще нет
```

Загрузчик обходит `cases/` на два уровня и берет папки, где лежит `case.md`.
Глубже не идет: внутри папки кейса лежат исходные макеты, и рекурсия по ним
гоняла бы сотни мегабайт при каждой пересборке. Одна папка = один кейс.

**Собрали кейс — переложите папку в `published/`.** По этому же признаку
считается список неопубликованного: папки в `unpublished/`.

Все остальное в папке кейса (`Raw/`, `raw/`, файлы в корне) — исходные макеты, они
остаются на машине Николая. В репозиторий из `cases/` проходят только эти два файла,
это закреплено правилом в `.gitignore`. Картинки для сайта нарезаются
в `public/assets/cases/<slug>/` и коммитятся.

Старые кейсы оклейки живут иначе — в `src/data/cases.yaml` (legacy). Новые кейсы туда
не добавляются. Четыре кейса презентаций и брошюр сидят на рукописных конфигах
в `src/data/case-page-config.ts` — тоже наследие, для новых не нужно.

## Шапка case.md

```yaml
---
slug: website-kapital-inform        # URL: /cases/<slug>/
category: websites                  # websites | presentations | identity | packaging | car-wrap | print
categoryLabel: Сайт
segment: accounting                 # ключ сферы бизнеса клиента
segmentLabel: Бухгалтерские услуги
client: Капиталъ Информ
year: 2021                          # уходит в schema.org dateCreated — только число
location: Владивосток
accent: "#D0343A"                   # HEX, снятый с макета
publicationPermission: да           # можно с оговоркой: «да, без имени владельца»
---
```

Про `accent`. Он идет и в текст на белом (крупные цифры фактов, метки секций,
маркеры результата), и на темные подложки. Если у клиента фирменный цвет светлый —
желтый, лимонный, салатовый, — на белом он проваливается: `#F7BE00` дает 1,75:1.
Берите с макета второй фирменный цвет, который темнее. У Трубоварни так взят
темно-синий `#011D4C` вместо желтого. Обратный случай шаблон вытягивает сам:
на темных секциях акцент осветляется через `color-mix`.

## Разделы case.md

Заголовки второго уровня разбираются по точному тексту — переименовывать нельзя.

| Раздел | Формат | Где виден |
|---|---|---|
| `# Заголовок` | H1 | заголовок страницы, `<title>`, og:title |
| `## Короткое название` | абзац | список кейсов, «Следующий кейс», крошки |
| `## Короткое описание` | абзац | лид под H1 |
| `## SEO-описание` | абзац | meta description |
| `## Услуги` | список | в разметке страницы не выводится |
| `## Ключевые факты` | `1. Значение:` / `Подпись:` | три крупные цифры под лидом |
| `## Задача` | список | секция «Задача», по абзацу на пункт |
| `## Решение 1…N` | `**Заголовок:**` + абзац | карточки приемов под задачей |
| `## Результат` | список | секция «Результат» |
| `## Что было сделано` | список | секция «Состав работ» |
| `## Авторство и участники` | `Роль:` / `Имя:`, `Агентство:` | роли в составе работ, агентство не выводится |
| `## Ссылки и источники` | `- Подпись: значение` | на страницу не выводится |
| `## Внутренние заметки (не публикуется)` | абзацы | на страницу не выводится |

Грабли, на которые я наступил:

- **Вводка к «Результату» живет не в `case.md`.** Ее задает `resultIntro` в
  `src/data/case-page-config.ts`. Раздел `Внутренние заметки (не публикуется)`
  парсится в поле `internalNotes` и на страницу не идет.
- **`Ссылки и источники` не видны.** Из них берется только «Сайт клиента» — если
  значение начинается с `http`, оно уходит в schema.org `about.url`. Заглушка безопасна.
- **Четыре решения и четыре результата — оптимум.** Сетка `auto-fit minmax(240px, 1fr)`:
  пять результатов встают в пять узких колонок и текст жмется.
- **`year` попадает в `dateCreated`.** Писать туда «нет данных» нельзя — сломается разметка.
- **YAML в `gallery.yaml` спотыкается о двоеточие.** `ctaText: Расскажите, где жить знак:
  печать, сайт` — ошибка сборки. Такие строки в кавычки или в блок `>-`.

## gallery.yaml

```yaml
assetRoot: /assets/cases/<slug>
cover: { src: <файл>.webp, alt: ... }   # лежит в корне assetRoot, не в full/
og: <файл>.webp
ogAlt: ...
keywords: ...
resultTitle: ...                         # заголовок секции «Результат»
ctaTitle / ctaText / ctaButton: ...
compare:                                 # секция «до — после», необязательная
  title: ...
  intro: ...
  items:
    - { number: '01', title: ..., text: ..., before: <файл>, after: <файл>,
        beforeAlt: ..., afterAlt: ... }
groups:
  - id: home
    title: ...
    intro: ...
    layout: slides                              # необязательно, см. ниже
    items:
      - { file: <файл>, label: ..., tall: true }   # tall необязателен
related:                                   # соседние кейсы того же клиента
  title: ...
  intro: ...
  items:
    - { slug: <slug соседнего кейса>, label: ..., text: ... }
```

Пути собираются сами: `assetRoot/full/<file>.webp` и `assetRoot/thumb/<file>-thumbnail.webp`.
Расширение и папку в `file` писать не надо.

Раскладка группы выбирается автоматически: если хоть у одного элемента `tall: true` —
вся группа идет макетом `tall` (4:5, картинка целиком). Иначе `screens` (16:10, видно
верх картинки, целиком — в просмотрщике). **Длинные страницы целиком кладите
в группу без `tall`** — иначе страница на 1:4 сожмется в невидимую полоску.

Автоматику можно перебить полем `layout`: `screens`, `tall`, `slides`, `brochure`,
`portrait`. Нужно там, где автоматика мажет:

- **Слайды и развороты 16:9** (страницы гайдбука, презентации) — `layout: slides`.
  В `tall` они летербоксятся до 45% плитки: вокруг пустое поле, картинка мелкая.
  В `screens` (16:10) обрезается по 5,6% с каждого края — у гайдбука это съедает
  левую колонку навигации. `slides` дает ровно 16:9 и четыре штуки в ряд.
- **Вертикальные файлы** (логотипы, модалки) — `layout: tall`.

Раскладки `tall`, `brochure` и `portrait` вписывают картинку в плитку целиком,
поэтому при несовпадении пропорций по краям остаются полосы фона плитки. Лечится
полем `ratio` у группы — пропорция плитки под размер картинок, в виде CSS
`aspect-ratio`:

```yaml
groups:
  - id: logo
    layout: tall
    ratio: 8 / 9      # файлы 890x1001, в штатных 4:5 давали серые полосы
```

Значение снимайте с самих файлов, а не на глаз. Если внутри группы пропорции
чуть разъезжаются, берите середину разброса: при заданном `ratio` картинка
заполняет плитку, и расхождение уходит в срез по краю, а не в полосу. Уже
проставлено: `8 / 9` у знаков Green Power и Трубоварни, `1 / 1` у знаков для
этикетки, `5 / 6` у модалок Japan Шина, `210 / 297` у страниц брошюры М-Инвест
(она на рукописном конфиге, поле задается там же). Раскладки `screens`, `slides`
и `default` картинку обрезают, а не вписывают, — полос там не бывает и `ratio`
им не нужен.

## Пайплайн картинок

Скрипты лежат в `tmp/`, у каждого в шапке своя инструкция. Порядок такой:

```bash
node tmp/scan-cases.mjs [часть имени папки]                          # размеры и вес исходников
node tmp/preview-strips.mjs "<макет>" tmp/preview/<имя> 900 1500     # читаемые полосы — смотреть глазами
node tmp/detect-gaps.mjs "<макет>" 100                               # резы по пустым полосам
node tmp/edge-runs.mjs "<макет>" 12 60                               # границы секций по цвету левого края
node tmp/band.mjs "<макет>" <top> <bottom> tmp/preview/band.webp 100 # полоса с линейкой по Y
node tmp/pick-color.mjs "<макет>" <left> <top> <w> <h>               # акцентный цвет с макета
node tmp/slice.mjs tmp/slices/<slug>.json                            # нарезка в full/ + thumb/ + обложка
node tmp/check-page.mjs "dist/cases/<slug>/index.html"               # проверка собранной страницы
```

Про границы резов. `detect-gaps.mjs` ищет строки однородного фона и на белых секциях
работает отлично. На цветных подложках и диагональных фигурах он слепнет — там
помогает `edge-runs.mjs` (границы по цвету левого края) и `band.mjs` (вырезает полосу
с линейкой, чтобы уточнить границу глазами). У «Капиталъ Информ» из 14 границ
главной четыре пришлось добирать вручную именно так.

Параметры нарезки: `fullWidth: 1440`, `thumbWidth: 640`, качество 82/72. Обложка —
16:9, `fit: contain` по белому фону, чтобы не резать макет по краям. Конфиги нарезки
лежат в `tmp/slices/<slug>.json` и коммитятся: по ним кейс перенарезается заново.

Пример конфига — `tmp/slices/kapital-inform.json`: два длинных макета, разложенных
по блокам, и семь страниц целиком одним блоком каждая.

**Сверьте размеры дизайна и вайрфрейма перед тем, как искать границы дважды.**
У Трубоварни оба макета оказались 3840×9458 — вайрфрейм рисовался в том же фрейме,
геометрия совпадает пиксель в пиксель. Один набор координат режет оба, и пары
в секции «до — после» сходятся сами. У Japan Шина размеры разошлись, там границы
искались отдельно. Проверить: `node tmp/scan-cases.mjs <часть имени папки>` —
скрипт сам находит папки кейсов в обеих группах.

Обложка: если у макета вверху сплошная цветная плашка, режьте ровно по ее границе
и задайте `background` тем же цветом. Тогда `fit: contain` дополнит поля в цвет
и обложка выглядит цельной, а не полосой с белыми краями.

## Подключить кейс

1. Добавить `slug` в `caseCatalogOrder` — `src/data/case-catalog.ts`. Порядок задает
   и позицию в портфолио, и цепочку «Следующий кейс».
2. Если сфера бизнеса клиента новая — добавить в `spheres` в `src/data/taxonomy.yaml`.
   `segment` из `case.md` сначала ищется в `sphereBySegment`, при промахе используется
   как есть. Не подбирайте приблизительную сферу — добавьте новую.
3. Добавить ссылку на кейс в `public/llms.txt`, в раздел своего направления.
   Забудете — сборка не пройдет: `npm run build` начинается с `scripts/check-llms.mjs`,
   и он называет недостающие строки поименно.
4. Прогнать `node scripts/make-cover-sizes.mjs`. Скрипт кладет рядом с обложкой
   копию на 800 px, из нее собирается `srcset` в карточках. Не запустите — телефон
   скачает обложку в полный размер.
5. Если кейс попадает в тройку избранных на странице услуги — поменять slug
   в массиве `featured…Slugs` на этой странице. На каждой услуге показываются
   три кейса, в схему `ItemList` уходят все.

Списка клиентов руками больше нет: блок «С кем работаю» на главной считает сферы
и заказчиков из кейсов сам.

## Счетчики: где какие числа

Правило: **числа на сайте не пишутся руками.** Каждое количество кейсов и работ
считается из данных при сборке. Если натыкаетесь на зашитое число — переводите
его на счет, а не правьте цифру. Иначе оно молча устареет: плашка «Сайты —
1 кейс в портфолио» провисела так две публикации.

Что уже считается само и трогать не нужно:

| Где | Что |
|---|---|
| `index.astro`, блок «Пять направлений» | плашка каждого направления, «скоро» при нуле кейсов, «Смотреть кейс» против «Смотреть направление», лид «По N направлениям работы уже опубликованы» |
| `index.astro`, `proof-nums` | «N разобранных кейсов в портфолио» |
| `portfolio.astro`, `p-lede` | «в каталоге уже N подробных кейсов», числительное словом |
| `portfolio.astro`, `p-meta` | направления, проекты, сферы |
| `portfolio.astro`, список направлений | счетчик кейсов, признак «скоро» |
| `index.astro`, блок «С кем работаю» | сферы, число кейсов в каждой, имена заказчиков |
| `ReturningClients.astro` | цепочки повторных заказов, заголовок «N проектов для одного клиента», подпись «каждый N-й кейс» |
| `identity.astro`, `websites.astro`, hero | «N кейсов в портфолио» |

**Ракурсы оклейки из `gallery.yaml` не считаются работами.** Раньше их число
выводилось рядом с кейсами — «5 кейсов · 28 работ» в списке направлений, «28 работ
крупным планом» в шапке портфолио, «N работ» на карточке каждого кейса оклейки.
Это виды одной и той же оклейки, а не отдельные работы, поэтому счетчик убран
везде. Сетка «Все работы подряд» осталась — она показывает ракурсы, но их
не пересчитывает.

Руками остается только **выбор**, а не арифметика: тройка избранных кейсов
на каждой странице услуги (`featured…Slugs`) и подписи объема на карточках
(`caseMetaBySlug`) — этих строк нет в шапке кейса. Все количества считаются.

Отдельный сорт той же ошибки: **число, которое растет по проектам.** В hero упаковки
стояло «75 макетов отрисовано» по трем линейкам Green Power. Вышел кейс MICKING
с 365 макетами, и цифра стала неправдой, хотя формально ее никто не ломал.
Если число нельзя посчитать из данных, привязывайте его к одному проекту:
«365 макетов в линейке MICKING», а не «75 макетов» вообще.

## Один клиент — несколько кейсов

Комплексную работу разводите на отдельные кейсы: у Трубоварни это `identity-trubovarnya`
(логотип и гайдбук) и `website-trubovarnya` (сайт). Так работа попадает в два
направления сразу, а страницы не превращаются в километровую галерею.

Механика: **две папки** в `cases/published/`, каждая со своим `case.md`
и `gallery.yaml`, и **два `assetRoot`** в `public/assets/cases/`. Сырые макеты
остаются одной общей папкой клиента в `cases/unpublished/` — там нет `case.md`,
и загрузчик ее не видит.

Связываются кейсы блоком `related` в `gallery.yaml`. В нем достаточно `slug`:
заголовок и обложку соседа шаблон тянет из коллекции сам, поэтому они не разъедутся
с кейсом. Незнакомый `slug` роняет сборку с внятной ошибкой. Секция выводится после
«Состава работ» и попадает в меню страницы как «Этот же клиент».

Ставьте кейсы рядом в `caseCatalogOrder` — они встают рядом и в портфолио. Побочный
эффект: у одного из двух «Следующий кейс» ведет туда же, куда `related`.

## Верстка блоков

Правила выведены из переделок, а не из общих соображений. Каждое стоило одного
захода назад.

**Глобальное подчеркивание ссылок.** В `src/styles/tokens.css` стоит
`a { border-bottom: 1px solid currentColor }`. Любая своя ссылка, которая не должна
быть подчеркнута, обязана сбросить `border-bottom` или задать свой цвет. Иначе под
ней висит серый обрубок линии, не совпадающий ни с текстом, ни с границей блока.
`text-decoration: none` от этого не спасает: подчеркивание тут не декорация, а рамка.

**Одна строка списка — одно действие.** В список направлений портфолио была
добавлена вторая ссылка, на страницу услуги. В строке оказались стрелка вниз
(к отфильтрованным кейсам) и стрелка вправо (на другую страницу), в двадцати
сантиметрах друг от друга. Второе действие выносится отдельной строкой под список.

**Карточки в ряду одного размера.** Пять карточек направлений на главной стояли
как 2+2+2 и 3+3 в сетке из шести колонок: последние две были в полтора раза шире
первых, и обложки в них разъезжались по масштабу. Все пять по 2/6, вторая строка
центрируется явным стартом колонки.

**Сетка без сирот.** Четырехколоночная сетка процесса и пять шагов — пятый висит
один во втором ряду. Проверяйте число элементов против числа колонок:
`.steps--five` включает пять колонок, `2×2` спасает четыре карточки в сетке из трех.
То же с кейсами: три в ряд и четвертый снизу выглядит недоделкой.

**Язык сайта — нумерованные строки, а не плитки.** Список сфер сначала был собран
плитками 4×4 и выпал из общего вида, а последняя плитка висела одна. Переделан
в строки с тонкими линиями по образцу «Направлений каталога» в портфолио: номер,
крупное название, серая подпись, счетчик моношрифтом, стрелка. Список тянется
на любое число пунктов и не оставляет висячих элементов. Прежде чем рисовать новый
тип блока, посмотрите, нет ли на сайте готового паттерна под ту же задачу.

**Подписи и тач-цели.** Подписи капителью не мельче 11 px. Ссылка или кнопка —
не ниже 44 px, включая ссылки-стрелки внизу карточек: `min-height: 44px` на самой
ссылке, а не на карточке.

**Проверять на 1440 и 375.** Горизонтального скролла быть не должно нигде.
Смотреть не только скролл, но и элементы шире экрана: длинная подпись кнопки
в CTA кейса вылезала за границу на 28 px, потому что `white-space` не давал
ей переноситься.

## Мета и картинки

**Заголовок страницы.** До 60 знаков вместе с « · Kovtun.studio». Заголовок-тезис
из `case.md` для этого длинный: у кейсов `title` собирается как
«Кейс: <Короткое название> · Kovtun.studio», а тезис остается в H1. У статей для
этого есть поле `seoTitle` в шапке — заполняйте его, а не надейтесь, что `title`
поместится.

**Описание.** 150–160 знаков. Длинное `seoDescription` кейса режется по границе
предложения автоматически, но лучше сразу писать так, чтобы резать было нечего.

**Картинки.** Обложки идут через `srcset`: `coverSrcset` и `coverSizes`
в `src/lib/covers.ts`, копии на 800 px делает `scripts/make-cover-sizes.mjs`.
Все новые картинки — с `loading="lazy"`, кроме первой в первом экране, и с явными
`width`/`height`, чтобы страница не прыгала.

**Разрешение обложки.** Обложка кейса стоит первым экраном во всю ширину, поэтому
2400 px по длинной стороне — рабочий минимум, а собирать ее надо из самого крупного
исходника, какой есть в папке кейса. Растянутая мелкая отрисовка видна сразу: у Alaska
знак нарисовали на 800 px и увеличили до 1600 — белые контуры поплыли. Нужный
исходник нашелся в развертке коробки, там знак 2843 px. Ищите не только в папке
с логотипом: развертки, этикетки и баннеры часто крупнее.

**Не публиковать крупнее исходника.** Растянутый пиксель резкости не добавляет:
картинка остается такой же мягкой, а весит втрое больше. Целевые 1440 и 2400 px —
потолок, а не норма: если исходник 900 px, публикуется 900. Так нашлись 33 файла —
рендеры оклейки с 908 px, растянутые до 2400, и знаки Green Power с 554 px,
растянутые до 1440. Ширина в `srcset` берется из заголовка самого webp
(`webpWidth` в `src/lib/covers.ts`), поэтому размер файла и обещание браузеру
не расходятся.

**Alt.** Обязателен у каждой картинки. Пустой `alt=""` допустим только у декора,
рядом с которым уже стоит тот же текст. Двадцать семь обложек кейсов в портфолио
висели без `alt` и были невидимы для поиска по картинкам.

**OG-картинка.** У каждой страницы услуги своя, 1200×630. Одна общая на три услуги
означает, что ссылка на упаковку, стиль и сайты выглядит в мессенджере одинаково.

## Новая страница или блок

Страница услуги не готова, пока не связана с остальным сайтом. Проверьте по списку:

1. Пункт в меню «Услуги» — `nav` в `src/data/site.yaml`, с картинкой превью.
2. Карточка направления на главной — `directionContent` в `index.astro`,
   с ценой в плашке и ссылкой на страницу, а не на фильтр портфолио.
3. Ссылка в общем футере (`site.yaml`) и в футерах остальных страниц услуг.
4. Строка в `public/llms.txt`: сама страница в разделе «Страницы» и блок цен,
   если у услуги есть публичный прайс.
5. Схема на странице: `Service` с `offers`, `FAQPage`, `ItemList` кейсов.
   `LocalBusiness` добавляет `BaseLayout`, дублировать не нужно.
6. Крошки и CTA кейсов этого направления ведут на страницу услуги — привязка
   в `servicePageByDirection`, `src/data/case-catalog.ts`.

## Тексты

Порядок: сначала скилл `info-style`, потом `web-copywriting`, в конце `humanizer`.
Тот же порядок у статей блога — он описан в скилле `seo-stati-dlya-bloga`, шаги 6 и 7.

**Скиллы открывать, а не вспоминать.** Правила из них по памяти воспроизводятся
процентов на семьдесят, и мимо проходит именно то, что ловит машинный текст:
оценки без факта, канцелярит, тире-вставки, панчлайны. Проверено на статье про
штрихкод 04.09.2026: формальные проверки (Ё, «не X, а Y», «это», объем) прошли
чисто, а открытые следом три скилла дали 19 правок, включая выдуманную цифру.
В отчете о сдаче называть, какие скиллы открыты и сколько правок дал каждый.

`humanizer` идет последним и снимает следы машинного письма. Его жесткие запреты:
буква Е вместо Ё без исключений, конструкции «не X, а Y», слово «это» как филлер,
лишние тире-вставки (грамматические тире можно), панчлайны «под цитату», канцелярит,
рубленые фразы. Прогонять через него и `case.md`, и подписи в `gallery.yaml`.

Что реально всплывает на этом материале:

- **Не выдумывать.** Цифры — только с макета или из объема работы. Нет данных —
  «нет данных». Нет цифр по трафику и конверсии — так и сказать, и объяснить почему.
- **Заголовок = тема + польза**, по шаблону «X, где Y»: «Сайт бухгалтерской компании,
  где новая страница не требует нового дизайна».
- **Сверьте новый заголовок с уже опубликованными.** Шаблон «X, где Y» затягивает
  в повтор: у сайта Трубоварни первая версия читалась «где новая услуга не требует
  нового дизайна» — почти дословно как у «Капиталъ Информ». Два кейса подряд с одной
  формулой выглядят штамповкой, второй надо переписать на другую выгоду.
- **`Короткое название` начинается с типа работы.** «Сайт Капиталъ Информ»,
  «Брошюра М-Инвест», «Фирменный стиль Трубоварни Еремеевой». Это поле идет
  в крошки, в разметку BreadcrumbList и служит текстом ссылки везде, откуда
  ведут на кейс, — в портфолио, в блоке работ на странице услуги, в «Следующем
  кейсе». Голое «М-Инвест» в ссылке не говорит поисковику ничего о странице,
  а у одного клиента кейсов может быть несколько: у Трубоварни их два, и без
  типа они бы назывались одинаково. Кавычки и предлоги оставляйте там, где
  без них хуже по-русски: «Презентация «Тернейский фермер»».
- **Активный залог.** «Правили на схемах», а не «спорные места правились».
- **Имена и числа вместо неопределенного.** «Рекламой занималось агентство lead+»,
  а не «отдельная команда».
- **Проверять факты в подписях.** Заголовок группы «Восемь страниц» над семью
  картинками — реальная ошибка, которую я поймал только на втором проходе.
- **Сверять утверждения с макетом.** «Развели цветом» — а развели рамкой и тенью.
- **Заголовок блока называет содержание, а не намекает.** «Один угол, который держит
  все носители» звучит красиво и не говорит, о чем абзац. Стало «Сколько места
  оставлять вокруг знака: охранное поле». Проверка простая: закройте текст и оставьте
  заголовок — понятно, о чем речь?
- **Обещали конкретный пример — покажите его.** Блок «что клиент делает по гайдбуку
  сам» описывал страницы гайдбука словами. Правило доказывает картинка страницы,
  а не абзац про нее.
- **Считайте вхождения «не X, а Y» по странице.** На страницах стиля и сайтов их
  было по двадцать штук: это первый признак машинного текста. Оставляйте там, где
  противопоставление и есть смысл блока («Программный продукт, а не сайт»), остальное
  переписывайте утверждением.

## Проверка и деплой

Локально:

```bash
npm run build
node tmp/check-page.mjs "dist/cases/<slug>/index.html"
```

`npm run build` — это не только сборка. До нее идет `scripts/check-llms.mjs` (кейс
или статья должны быть в `llms.txt`), после — `scripts/check-llms-links.mjs` (все
внутренние ссылки из `llms.txt` ведут на существующие страницы) и
`scripts/check-content.mjs` (title до 65 знаков, description 70–165, картинка
без `alt`, лишний `h1`). Любая из проверок роняет сборку и называет страницу
и нарушение поименно. Не обходите их правкой скриптов: правило записано в этом
файле, а проверка — его машинная половина.

Проверка ловит меру, но не смысл. Верстку блоков, заголовки разделов и честность
цифр смотреть глазами по разделам «Верстка блоков» и «Тексты».

Дев-сервер поднимается через preview-инструменты по имени
`design.kovtun.studio (dev)`, порт 4321 (занят — подберется свободный).
Есть и `design.kovtun.studio (preview)` — он отдает собранный `dist/`,
а не исходники.

После пуша в `main` деплой на GitHub Pages идет минуту. Живые страницы отдаются
с `Cache-Control: max-age=600`, поэтому правка может не показаться сразу: смотреть
через Ctrl+F5 или в приватном окне, а не решать, что деплой не прошел.

Имена берутся из `.claude/launch.json`, и инструмент читает тот файл, что лежит
в рабочей папке сессии. В репозитории есть свой — он сработает, если открыть
папку проекта. Если сессия открыта уровнем выше, сработает `launch.json` оттуда.
Имена в обоих одинаковые, поэтому команда одна и та же в любом случае.

**Страницу надо посмотреть глазами, а не только прогнать check-page.** Он ловит
битые пути и пустые `alt`, но не видит, что текст слился с фоном или что картинки
в галерее ужались. Если панель браузера не отдает скриншот («the Browser pane is
not displayed»), рендерьте страницу целиком через headless Chrome и режьте
на полосы тем же `preview-strips.mjs`:

```bash
cd <папка вывода> && "/c/Program Files/Google/Chrome/Application/chrome.exe" \
  --headless=new --disable-gpu --hide-scrollbars --window-size=1440,13000 \
  --virtual-time-budget=8000 --screenshot=page.png "http://localhost:4321/cases/<slug>/"
node tmp/preview-strips.mjs "<папка>/page.png" "<папка>/strips" 1000 1700
```

Высоту окна берите с запасом от `document.documentElement.scrollHeight`. Chrome
кладет файл в свою папку установки, а не в текущую, — забирайте оттуда **по имени**.
Не выгребайте ту папку маской или рекурсивно: там лежат его собственные PNG
(`VisualElements/Logo.png` и соседи), их легко унести вместе со скриншотом.

Мобильную версию тоже посмотрите. Учтите: headless Chrome не опускает окно ниже
примерно 500px — при `--window-size=375` страница верстается шире, а скриншот
просто обрезается по 375, и получается ложная картина «текст вылезает».
Для картинки берите 500px (брейкпоинт мобильной раскладки — 900px, так что
раскладка та же), а точные величины снимайте через preview-инструменты
на настоящих 375: ширины, отступы и `scrollWidth` против `clientWidth`.

Деплой = пуш в `main`. GitHub Actions (`.github/workflows/deploy.yml`) сам ставит
зависимости, собирает и публикует на GitHub Pages. Живой адрес —
https://kovtun.studio

Коммитить: `cases/published/<Папка>/case.md`, `cases/published/<Папка>/gallery.yaml`,
`public/assets/cases/<slug>/`, правки в `src/`. Добавлять файлы по именам, а не
`git add .` — сырые макеты хоть и скрыты правилом, привычка вредная.
